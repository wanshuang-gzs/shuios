# 构建指南

从零到一张可启动的 shuios 镜像。本文按"你在什么环境下"分两条路。

---

## 0. 检查清单

| 需要 | 说明 |
| --- | --- |
| 磁盘 | 至少 25 GB 空闲（Buildroot 源码 + 内核 + 工具链 + WebKitGTK 构建树） |
| 内存 | 4 GB 起，8 GB 舒适；**含 WebKitGTK 的全量构建建议 16 GB + 16 GB swap** |
| 时间 | 不含 WebKitGTK：首次 40~90 分钟（20 核约 25 分钟）。含 WebKitGTK：以"天"计（本机 20 核 / 15 GB + swap 实测跨约 40 小时），之后增量重建是分钟级 |
| 网络 | 需要访问 buildroot.org / kernel.org / crates.io / webkitgtk.org |

---

## 1. 路线 A：原生 Linux

```bash
git clone <本仓库> shuios && cd shuios

make deps      # Debian/Ubuntu：编译器、wget、bc、ncurses、qemu、ovmf…
make fetch     # 下载解压 Buildroot 到 ./buildroot
make rust      # 编译 shuiosd / shui / shui-ctl → br2-ext/artifacts/
make build     # 配置 + 构建 + 出镜像
make run       # QEMU（UEFI 固件：OVMF）
```

产物：

| 路径 | 内容 |
| --- | --- |
| `output/images/shuios.img` | 完整磁盘镜像（GPT：ESP + squashfs 根 + ext4 数据） |
| `output/images/rootfs.squashfs` | 只读根文件系统 |
| `output/images/boot.vfat` | ESP 内容（可直接换启动器） |

---

## 2. 路线 B：Windows + WSL2

Windows 上没有 chroot、没有 `mksquashfs`，必须借 WSL2 的 Linux 内核。

### 2.1 装 WSL2（一次性）

**关键：启用 WSL 可选功能后必须重启一次**，否则 `wsl.exe` 会一直报
「未安装适用于 Linux 的 Windows 子系统」，即使 `dism` 明确返回成功。
判断是否待重启：

```powershell
Test-Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing\RebootPending'
```

三种可行路径，任选其一：

**A. 全自动（推荐，仓库自带脚本）**

```powershell
# 1) 管理员 PowerShell：启用功能
.\tools\install-wsl.cmd        # 右键 -> 以管理员身份运行
# 2) 重启一次
Restart-Computer
# 3) 重启后：管理员 PowerShell 安装 WSL 运行时
.\tools\wsl-post-reboot.ps1    # 或：Start-Process powershell -Verb RunAs
# 4) 普通权限：把构建发行版导入到 D:\wsl（不占 C 盘）
.\tools\wsl-import-distro.ps1
```

**B. 手动**

```powershell
# 管理员
dism /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all
dism /online /enable-feature /featurename:VirtualMachinePlatform /all
# 重启，然后（管理员）
wsl --install --no-distribution          # 走 Store 通道，国内通常比 --web-download 快
wsl --set-default-version 2
```

**C. 只装 WSL1（不推荐）**：`wsl --import ... --version 1`。WSL1 缺少
`mount`/`chroot` 等能力，Buildroot 的部分步骤会失败。

> **实测踩坑记录**（这台机器上真发生过，留档备忘）：
>
> | 现象 | 根因 |
> | --- | --- |
> | UAC 点了「是」但 PowerShell 什么都没做、无日志 | `.ps1` 是 UTF-8 **无 BOM** 且含中文；Windows PowerShell 5.1 按 GBK 解读时会「吃掉」紧跟的引号，脚本解析失败后直接退出。**所有 .ps1 必须纯 ASCII 或带 BOM** |
> | `wsl --install` 打印「请运行 wsl --install」并 exit 1 | 可选功能已启用但未重启（`RebootPending=True`） |
> | `wsl --install --web-download` 卡在「按任意键安装…」 | 交互提示在等键盘；把 stdin 接到 NUL 即可让它快速失败/通过 |
> | `winget install Microsoft.WSL` 极慢 | winget 清单指向 GitHub Release（519 MB），直连仅 ~25 KB/s |
> | Buildroot 源码下载要半小时 | kernel.org/gnu.org 直连 ~29 KB/s，清华 TUNA ~3.8 MB/s；用 `tools/fetch-deps.sh` + `BR2_PRIMARY_SITE` |

### 2.2 导入构建用的发行版（放到 D: 盘）

```powershell
# 1) 下载 Ubuntu 云镜像 rootfs
curl.exe -L -o D:\wsl\ubuntu-rootfs.tar.gz `
  https://cloud-images.ubuntu.com/wsl/noble/current/ubuntu-noble-wsl-amd64-ubuntu24.04lts.rootfs.tar.gz
# 2) 导入
wsl --import shui-build D:\wsl\shui-build D:\wsl\ubuntu-rootfs.tar.gz --version 2
wsl -d shui-build
```

### 2.2 在 WSL 里准备

```bash
apt-get update && apt-get install -y build-essential git wget cpio unzip rsync bc \
    libncurses-dev file python3 libssl-dev qemu-system-x86 ovmf dosfstools mtools \
    e2fsprogs patch perl curl
# Rust（原生编译我们的组件）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source "$HOME/.cargo/env"
```

### 2.3 把仓库放进 WSL 的 ext4 里构建

**不要**在 `/mnt/d/...` 上直接跑 Buildroot：9p 文件系统会让构建慢 5~10 倍。
正确做法是把源码复制进去，构建完再把镜像拿回来：

```powershell
# Windows 侧
wsl -d shui-build -u root -- bash -c "mkdir -p /root/shuios"
tar -cf - -C D:\shuios --exclude=target --exclude=output --exclude=buildroot . |
    wsl -d shui-build -u root -- tar -xf - -C /root/shuios
wsl -d shui-build -u root -- bash -c "cd /root/shuios && make deps && make fetch && make rust && make build -j\$(nproc)"
# 取回镜像
wsl -d shui-build -u root -- cp /root/shuios/output/images/shuios.img /mnt/d/shuios/shuios.img
```

## 3. 构建过程中的关键点

### 3.1 Rust 组件为什么预编译

`tools/build-rust.sh` 在构建主机上 `cargo build --release`，产物放进
`br2-ext/artifacts/`，再由 Buildroot 的 `shuios-runtime` 包安装。

理由：目标架构 x86_64 与构建主机一致；原生编译比在 Buildroot 里维护另一套
Rust 交叉工具链更快更稳。**代价**：交叉到 aarch64 时需要改这条流水线
（`--target aarch64-unknown-linux-gnu` + 交叉链接器），见路线图 v0.3。

### 3.2 首次构建会失败在哪些地方（及处理）

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| `缺少预编译二进制` | 没跑 `make rust` | 先 `make rust` |
| `BR2_PACKAGE_SHUIOS_RUNTIME` 未定义 | `BR2_EXTERNAL` 没传对 | 检查是否指向 `br2-ext` |
| `warning: trying to assign nonexistent symbol` | defconfig 里的选项名在该 Buildroot 版本不存在 | 用 `make menuconfig` 保存一次以归一化 |
| 内核编译 OOM | 并行度过高 | `make -j4` |
| WebKit 编译 OOM / 卡死 | WebKitGTK 单文件链接峰值很高 | `BR2_JLEVEL=8` + 16 GB swap（本机 15 GB 内存实配） |
| `genimage: not found` | 缺 `BR2_PACKAGE_HOST_GENIMAGE` | 已内置，若报错先 `make clean` 重来 |

### 3.2.1 WebKitGTK 与 shui-browser

镜像里带 WebKitGTK 2.48.6（Wayland / HTTPS / GStreamer 多媒体），
浏览器外壳是本地包 `shui-browser`。相关文件：

| 路径 | 作用 |
| --- | --- |
| `br2-ext/configs/shuios_x86_64_defconfig` | `BR2_PACKAGE_WEBKITGTK*`、`BR2_PACKAGE_SHUI_BROWSER` |
| `br2-ext/package/shui-browser/` | C 源码（`src/shui-browser.c`）、起始页 HTML、`.mk` |
| `br2-ext/package/shui-browser/src/shui-browser.c` | 外壳：标签、地址栏、下载气泡、错误页 |

日常改浏览器**不要全量构建**：

```bash
# WSL 里，约 20 秒；第一个参数是 VM 当前 IP
bash /mnt/d/shuios/tools/dev-deploy-browser.sh 192.168.172.135
```

Buildroot 的 `SITE_METHOD=local` 有个坑：`make shui-browser-rebuild`
**不会重新同步源码**。`dev-deploy-browser.sh` 会先把 `src/` rsync 进
`br2-ext` 和 `output/build/shui-browser-0.1.0/`；手工构建时也要照做。
`shuios-runtime` 这类纯脚本包同理：改了文件要先
`make shuios-runtime-reinstall`，否则镜像里还是旧脚本。

### 3.2.2 音频（VMware HDA + ALSA）

音频要三段同时具备，缺一段就是"没有声卡"：

1. **VM 硬件**：`.vmx` 里必须有 `sound.present = "TRUE"`、
   `sound.virtualDev = "hdaudio"`。`tools/run-vmware.ps1` 每次启动前会校正；
   QEMU 需在命令行加 `-audiodev`/`-device`（当前 QEMU 脚本没挂声卡）。
2. **内核**：`x86_64_defconfig` 只带 `snd-hda-intel` 控制器，
   codec 解析器默认全关。`kernel-shuios.fragment` 里开了
   `SND_HDA_GENERIC` + 常用 codec（REALTEK/ANALOG/SIGMATEL/VIA/CIRRUS/
   CONEXANT/CA0132/HDMI），另带 `SND_ENS1371` 与 `SND_USB_AUDIO`。
3. **用户态**：defconfig 里 `BR2_PACKAGE_ALSA_UTILS=y` 及
   `_AMIXER/_APLAY/_SPEAKER_TEST`，并加 `BR2_PACKAGE_PIPEWIRE`、
   `BR2_PACKAGE_WIREPLUMBER`、`BR2_PACKAGE_PULSEAUDIO`
   （`_DAEMON` 关闭，只要客户端库）、
   `BR2_PACKAGE_GST1_PLUGINS_GOOD_PLUGIN_PULSE`。Buildroot 装的系统级
   `pipewire.service` / `wireplumber.service` 等会先占住 HDA，post-build 里
   统一 mask（`ln -sf /dev/null`），由 `shuios-session.sh` 在会话内拉起
   pipewire → wireplumber → pipewire-pulse；Pulse 插件文件名是
   `libgstpulseaudio.so`。

验证（在会话运行目录下）：`cat /proc/asound/cards`、`aplay -l`、
`XDG_RUNTIME_DIR=/run/shuios/compositor wpctl get-volume @DEFAULT_AUDIO_SINK@`、
`pactl info`（应显示 PulseAudio on PipeWire）。
`/etc/asound.conf` 把 default PCM/CTL 指到 PipeWire，多程序自动混音；
`speaker-test -l 1` 播完不退出，要自己加 9 s 看门狗。本次实测见 docs/05 V26。

### 3.2.3 远程 AI（curl + OpenSSL + CA）

远程提供商由 `shui-llm` 调镜像里的 `/usr/bin/curl` 发出，Rust 侧不带 TLS
栈。defconfig 必须成组打开，少一个都会在运行期才暴露：

```c
BR2_PACKAGE_LIBCURL=y
BR2_PACKAGE_LIBCURL_CURL=y       # 子选项；没有父项会被静默丢弃
BR2_PACKAGE_LIBCURL_OPENSSL=y    # 换 TLS 后端要 dirclean 重编
BR2_PACKAGE_CA_CERTIFICATES=y
```

验证：

```bash
curl --version                                  # 应出现 OpenSSL 与 HTTP/2/PSL 等特性
ls /etc/ssl/certs/ca-certificates.crt           # CA bundle
shui-ctl ai test                                # 远程无密钥时应返回 HTTP 401/403 而不是 TLS 错误
```

改过 libcurl 选项后要 `make libcurl-dirclean` 再构建，否则旧 stamp 会复用
没有 TLS 的二进制。本次实测见 docs/05 V27。

### 3.3 归一化 defconfig

Buildroot 版本间选项会变。第一次跑通后，用这条命令把配置收敛成"只含必要项"：

```bash
make -C buildroot BR2_EXTERNAL=$(pwd)/br2-ext shuios_x86_64_defconfig
make -C buildroot BR2_EXTERNAL=$(pwd)/br2-ext menuconfig   # 需要改动就改
make -C buildroot BR2_EXTERNAL=$(pwd)/br2-ext savedefconfig
cp buildroot/output/defconfig br2-ext/configs/shuios_x86_64_defconfig
```

## 4. 在 QEMU 里验证

```bash
tools/qemu-run.sh output/images/shuios.img
```

预期看到：

1. GRUB 菜单（`shuios 0.1 「泉」`）；
2. 内核日志滚过，最后是 systemd 启动；
3. 自动登录后进入 `shui`，提示符是 `氵 `。

验证清单：

```bash
shui-ctl ping                  # 控制平面活着
shui-ctl sys                   # 只读根应显示"是"
shui-ctl call fs.list '{"path":"/workspace"}'
shui-ctl spawn sleeper sleep 300
shui-ctl agents                # 应看到 sleeper 与它的内存/CPU
shui-ctl kill sleeper
```

`只读根` 一项如果显示"否"，说明 squashfs 被挂成了可写，检查
`rootfstype=squashfs` 与 fstab 的 `ro`。

## 5. 写到真机

```bash
sudo dd if=output/images/shuios.img of=/dev/sdX bs=4M status=progress oflag=sync conv=fsync
```

注意：

* **`/dev/sdX` 一定确认再确认**，写错盘会毁掉数据；
* 镜像的 GRUB 里 `root=/dev/sda2` 是按 SATA/USB 命名的。NVMe 机器需要
  把根参数改成 `root=/dev/nvme0n1p2`（启动菜单里按 `e` 临时代入即可）；
* v0.1 只做 UEFI 启动。老 BIOS 机器需要额外加 MBR/BIOS 引导，见路线图。

## 6. 常用调试手法

```bash
# 进 rescue 模式（GRUB 菜单里有）
# 或临时加内核参数：systemd.unit=rescue.target

# 串口日志（QEMU 里 console=ttyS0 已开启）
tools/qemu-run.sh output/images/shuios.img | tee boot.log

# 只看 shuiosd
journalctl -u shuiosd -f

# 看某个智能体被限制住没有
cat /sys/fs/cgroup/shuios/<name>/memory.max
cat /sys/fs/cgroup/shuios/<name>/memory.current
```
