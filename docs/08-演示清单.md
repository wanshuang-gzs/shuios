## 0. 一键启动

```powershell
# 首选：VMware Workstation 17（3D 档）。首次启动会把 raw 转成 vmdk，约 1 分钟
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run-vmware.ps1

# 备选：QEMU（bochs VGA + WHPX，无 VMware 也能跑）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run-vm.ps1
```

- 分辨率固定 1280×800，默认会话 **swayfx + 底部 40px 任务栏 `shui-panel`**
  （layer-shell，无顶栏、无 Dock）；开机只起任务栏与空闲守护 `shui-idle`，
  不预开应用。`Win+L` 锁屏，空闲 600 s 自动锁定。
- 停机：VMware 用 `tools\run-vmware.ps1 -Stop`；QEMU 直接关窗口（或在 guest 里
  `systemctl poweroff`）。
- 调试登录：guest 里 root 密码 `shui`；QEMU 默认把 22 端口映射到宿主机 10022。

### 1.5 网络管理（V22 新增）

V22 交付时只有命令行；V23 起可用 `shui-settings` 的图形页（见 1.6），
以下保留 `nmcli` 演示步骤。测试环境用 mac80211_hwsim + hostapd 造 AP
（SSID `shui-test`，WPA2-PSK `shui12345`），真机上换成实际路由器即可。

| # | 演示动作 | 期望结果 | 实测证据 |
| --- | --- | --- | --- |
| 30 | 插网线开机（VMware NAT） | NM 自动 DHCP：`GENERAL.STATE 100`，连接名「Wired connection 1」，拿到 `192.168.172.131/24`，可解析外网域名 | [有线 + DNS](assets/v22/03-wired-dns.png) |
| 31 | `nmcli dev wifi rescan ifname wlan0 && nmcli dev wifi list` | 列出周围 AP（SSID/SIGNAL/SECURITY/CHAN），`shui-test` 为 WPA2 ch6 | [扫描](assets/v22/02-wifi-scan.png) |
| 32 | `nmcli dev wifi connect shui-test password shui12345 ifname wlan0` | `state 100 connected`；`iw dev wlan0 link` 显示 `Connected to …`、SSID、频点；nmconnection 以 `0600` 落在数据分区，重启保留 | [连接](assets/v22/01-wifi-connect.png) |
| 33 | 隐藏 SSID：AP 设 `ignore_broadcast_ssid=1`，`nmcli con up shui-test` | 定向扫描后仍能加入，`state 100`；重启后配置在，显式激活即可重连 | 文本记录（说明见 `docs/05` V22） |

要点：`systemctl is-active NetworkManager wpa_supplicant systemd-resolved` 均为
`active`，`systemd-networkd` 为 `inactive`；DNS 走 resolved stub
（`/etc/resolv.conf → ../run/systemd/resolve/stub-resolv.conf`）。
VMware 不向 guest 暴露 Wi-Fi 设备，镜像内的虚拟无线电验证不等同于真机无线，
真实网卡待实测（见 `docs/05` 尚未验证清单）。

密钥只存在 `/var/lib/shuios/state/ai.json`（0600），由 `shuiosd` 代发请求；
命令行只接受 `--key-stdin` 或 0600 文件，日志与 RPC 只出现末四位。
远程无密钥时 `ai.test` 返回服务端 HTTP 401/403（说明 TLS/CA 链路正常）；
真实远程提供商的成功对话仍需用户提供密钥（见 §3）。

## 3. 已知限制（不影响验收）

- **VMware 的鼠标输入无法自动化**：Workstation 17 自带 VNC 只出画面、不收输入
  （实测 RFB PointerEvent 发到 (800,400)，光标不动）。第 5/6/8 项请用真实鼠标点一下；
  渲染与布局已用 VNC 截图验证。拖动链路的自动化证据来自 QEMU（同一套合成器输入路径）。
- **vmwgfx 上硬件缓冲 EGL 客户端不可用**（`importing the supplied dmabufs failed`）；
  软件 GL（`LIBGL_ALWAYS_SOFTWARE=1`）和 GTK/foot 等 shm 客户端正常。
- QEMU 的 CPU 瓶颈在 llvmpipe：全屏 1280×800 软件渲染客户端约 37 fps；
  小窗口（250×250）能贴住 75Hz。真机 i915/amdgpu 自动走满效档 + 硬件 GL。
- foot 的标题栏是 GTK 默认浅灰（外观问题，不影响使用）。
- 浏览器没有 bubblewrap 沙箱（镜像未装 `bwrap`）；下载只有当前会话气泡，
  无历史/取消；虚拟 GPU 下走软件渲染，大页面滚动偏慢。
- 音频已切到 PipeWire（多程序混音 + 任务栏音量 + 设置声音页 + 重启保留），
  但只管理默认输出设备：没有设备切换 / 麦克风 / 单应用音量，也没有托盘弹层；
  持久化只覆盖 `shui-settings` / `shui-panel` 发起的修改（SSH 直接 `wpctl`
  改音量不会写状态文件）。宿主扬声器是否出声仍需人工听（guest 内
  ALSA→PipeWire→sink / pactl / GStreamer / WebKit 已自动验证）。
- 设置中心目前只有「网络 / 声音 / AI / 关于」四页（显示/电源/外观/键盘/语言
  后续补）；不支持 802.1X/WEP；隐藏 SSID 需先用 `nmcli` 定向配置；未做单实例
  （重复 Win+I 会开多个窗口）。测试 AP 无 DHCP，新建配置的自动取址未验；隐藏
  SSID 不会自动连接；真实无线网卡未实测（VMware 无 Wi-Fi 设备）。
- AI 只完成密钥链路与远程提供商接入：没有用真实服务商密钥跑通一次成功对话
  （已验证到 TLS/CA 与 HTTP 401）；本地 `.gguf` 的自动选型/启动未实测；只有
  一次性 chat，没有流式/取消/多轮持久化；没有远程模型列表，模型名手填；
  设置页不暴露 timeout/temperature（用 `shui-ctl ai set`）；密钥是 0600 明文
  文件、没有系统密钥环，`shuiosd` 以 root 运行。
- 任务栏：没有窗口缩略图与多窗口分组，同一应用多窗口只显示一个按钮；
  右键**直接关闭**（layer surface 不能弹 xdg_popup，暂无上下文菜单）；
  裸 Win 键未绑定开始菜单（`Super+D`）；托盘/音量弹层未做。
- 任务栏与开始菜单的点击在验收里用合成指针注入（VMware VNC 不收输入），
  宿主真实鼠标点按仍需人工过一遍。
- 锁屏：没有 `ext-session-lock`，不是合成器级安全锁；无 PAM/独立登录会话；
  密码尝试不限速；不关屏（无 DPMS）；不支持挂起/休眠/合盖；「注销」是重启
  sway 会话。宿主真实键盘解锁需人工过一遍（验收用合成虚拟键盘）。
