## v0.1「泉」— 能启动、能跑起来

**目标**：一个真正能开机、能管理智能体、能把自然语言变成系统操作的最小发行版。

- [x] Buildroot BR2_EXTERNAL 树（自建 rootfs，不基于任何发行版）
- [x] 只读 squashfs 根 + ext4 数据分区（`/workspace`、`/var/lib/shuios` 持久化）
- [x] UEFI + GRUB2 启动，磁盘镜像可直接 dd 到 U 盘
- [x] `shuiosd`：cgroup v2 限额、生命周期、日志、内置 MCP 工具
- [x] `shui`：自然语言 → 工具调用循环；`/命令` 与 `!命令` 双通道
- [x] `shui-ctl`：面向脚本的控制 CLI
- [x] systemd 集成：`shuiosd` / `shuios-storage` / `shuios-firstboot`
- [x] QEMU 验证路径（OVMF + 串口）
- [x] 首次构建成功 + 截图/录屏留档（V16–V19，见 `docs/05`）
- [ ] 内核 fragment 归一化（去掉无效符号）

**已知短板**

- 只做 UEFI，老 BIOS 机器不能启动
- 只做 x86_64
- 本地推理已集成 llama.cpp（`shuios-llama.service`），但未做端到端模型验收
- `capabilities` 字段只记录不强制

## v0.2「溪」— 能自我升级、能真正隔离

**目标**：让这台机器可以长期运行，而不是一次性演示。

### 桌面路线（2026-10-19 用户拍板：方案 A）

用户明确要求 v0.2 桌面"逐渐完整"：开关机动画、任务栏、桌面图标、
可视化启动器、软件安装。Buildroot 里没有现成桌面环境，因此选择
**保留极简底座 + 自研桌面**（而非换 Debian 底座）：

| 需求 | 方案 | 状态 |
| --- | --- | --- |
| 合成器 | **swayfx**（wlroots，支持 layer-shell）→ 默认；Weston 仅作兜底 | ✅ 可跑 |
| 任务栏 | **自研 `shui-panel`（layer-shell，layer TOP，40px）**；无顶栏/waybar | ✅ V24（窗口按钮、开始菜单、右键关闭） |
| 状态信息 | `shui-ctl bar`（Rust）输出状态格式，展示智能体数量/内存/只读根 | ✅ 实时显示 |
| 应用启动器 | **`shui-panel --menu` 开始菜单**；键盘启动器保留 | ✅ V24（应用网格 + 搜索 + 电源/锁屏/注销） |
| 锁屏 / 电源 | **`shui-lock`（layer OVERLAY + `/etc/shadow` 校验）+ `shui-idle`（空闲 600 s）** | ✅ V25 锁屏/注销/关机/重启；登录/休眠待做 |
| 桌面背景/图标 | **swaybg + 自研壁纸**（`tools/make-wallpaper.py` 生成） | 🟡 壁纸已上；图标层待做 |
| 开关机动画 | **自研 `shuios-splash`**（Buildroot 没有 plymouth 包，直接写 /dev/fb0） | ✅ 开机 + 关机都已验证 |
| 软件安装 | 自研 `shui-pkg`（基于我们的 A/B 镜像 + 包索引），而非再造 apt | ✅ 已实现（本地仓库 + HTTP 支持） |
| 软件商店 | 自研 GTK3 `shui-store`（图标由 Cairo 现画，点一下装/卸） | ✅ 已实现并验证 |
| 浏览器 | **`shui-browser`（WebKitGTK 2.48 + GTK3 外壳）** | ✅ V18 实测；无沙箱、软件渲染、DRM/兼容性待评估 |
| 音频 | **PipeWire 1.2.8 + WirePlumber 0.5.5 + pipewire-pulse**（ALSA 经 `asound.conf` 接入）；WebKit 走 GStreamer `pulsesink` | ✅ V26 实测：混音、任务栏/设置音量、静音、重启保留；无设备切换/麦克风/单应用音量 |
| 中文环境 | 中文字体 + `zh_CN.UTF-8` locale + fcitx5/Rime | ✅ V20 输入法已验收 |

原则：**每个新增桌面组件都要能被 `shui` 和智能体通过 MCP 工具操作**——
否则就退化成普通桌面发行版了。

1. **A/B 双根分区与原子升级** ✅ 已实现（待真机验证）
   - 布局：ESP + root-A + root-B + data，全部固定 PARTUUID
   - `shuios-update apply` 写非活动槽 → 改 grubenv → 重启生效
   - 状态机 `ok/try/booting`，新槽启动失败自动回滚，无需计数器
   - `shuios-bootok.service` 在新系统起来后提交

2. **推理服务** 🟡 本地已集成、远程已可用（本地待端到端模型验收）
   - 集成 llama.cpp（`llama-server`）为 `shuios-llama.service`
   - 模型自动从 `/var/lib/shuios/models` 注册并挑选
   - V27：新增 `shui-llm`，支持 OpenAI 兼容远程提供商（HTTPS，curl +
     系统 CA）；密钥只存 `/var/lib/shuios/state/ai.json`（0600），由
     `shuiosd` 代发请求，设置中心 / `shui-ctl` 管理
   - 远程成功对话仍待用户密钥；本地 `.gguf` 自动选型与启动仍未实测

3. **沙箱落地** ☐ 未做（v0.3 的 P0）
   - Landlock：把 `fs.write` 白名单变成内核级强制
   - 每智能体独立 mount namespace + 只读 bind 的 `/usr`
   - seccomp 基线策略（禁 ptrace/ptrace 跨进程）
   - 每智能体 UID（与 cgroup 配合，见未决问题）

4. **MCP 对外** ✅ 已实现（待真机鉴权验证）
   - `shuiosd` 在 `/run/shuios/mcp/system.sock` 提供标准 MCP（JSON-RPC 2.0）
   - 只暴露工具发现与调用，与完整控制平面物理隔离
   - 待办：外部智能体接入的鉴权（目前靠套接字文件权限 0660）

5. **可观测性** ☐ 未做（v0.3 的 P0）
   - `shui-ctl top`：实时看每个智能体的内存/CPU
   - 结构化审计：每次工具调用写 journal 字段 `SHUIOS_TOOL=...`

## v0.3「河」— 技术用户可日用（90 天）

**目标**：一个开发者愿意每天开机；20 个日常任务不打开终端；智能体可以安全地跑。
详细拆解与验收见 [`09`](09-产品规划与市场调研.md) §5.2、§6。

> 产能边界：1 人 + AI 在 90 天内只能覆盖 P0 的 60–70%；2 人 + AI 才能覆盖
> P0 + 部分 P1。第 6 周做裁剪评审；完整 L1 对 1 人约 4–6 个月。

**P0（必须）**

- 中文输入法（fcitx5 + rime，Wayland/GTK 可用）
- 文件管理器 `shui-files`（V21 已交付浏览/新建/重命名/删除/隐藏/打开；搜索/复制/回收站/U 盘待补）
- 设置中心 `shui-settings` MVP（V23 网络 + V26 声音 + V27 AI + 关于；显示/电源/外观/键盘/语言待做）
- NetworkManager + Wi-Fi UI（WPA2/3、隐藏网络、有线/静态 IP）
- layer-shell 任务栏 + 桌面图标 + 窗口列表 + 开始菜单网格/搜索
- 托盘 / 通知 / 亮度；截图 / 剪贴板（音量按钮 V26 已在任务栏落地，托盘弹层未做）
- 锁屏 / 电源（V25 已交付锁屏/注销/关机/重启；登录、休眠/合盖仍待做）
- ~~PipeWire + WirePlumber（多程序混音、音量持久化）~~ ✅ V26 已交付；输出设备切换/麦克风/单应用音量待补
- VA-API/GPU 加速（Intel/AMD），浏览器视频硬件解码
- 应用商店更新/搜索/分类
- AI 运行时 v1：~~API 密钥 / 远程提供商~~ ✅ V27 已交付；Landlock/seccomp、授权 UI、审计、模型管理、RAG、多智能体待做
- 备份/恢复 + 一键诊断

**P1（尽量）**

- 安装器 Beta（VM + 真机；保留数据）
- 打印 MVP（CUPS）
- 更新签名 + HTTPS 仓库 + 灰度
- 蓝牙音频、多显示器/HiDPI
- Web/PWA 办公与 IM（WPS/Office Web、微信/钉钉/飞书 Web）

**明确不做**

- aarch64 / legacy BIOS / ISO / PXE（移到 v1.0）
- 多用户 / LUKS / Secure Boot / 恢复模式（移到 v0.4）
- 3A 游戏、Adobe、专业 CAD/视频剪辑

## 刻意不做的事

| 不做 | 原因 |
| --- | --- |
| 通用桌面的全量复刻 | 不替代所有人的 Windows/macOS；做“智能体安全屋”式的 AI 原生桌面。但 L1 日用能力（输入法/文件/网络/设置/锁屏）仍必须补齐 |
| 自研 Office / 浏览器引擎 | 成本无底洞；用 Web/PWA、WebKitGTK、Wine（可选）和伙伴应用 |
| apt 式“就地装软件” | 只读根 + A/B + squashfs 包；`shui-pkg` 装的是可写数据分区上的只读挂载点 |
| 内置 Python/CUDA 全家桶 | 默认镜像要保持极小；按需加包 |
| 容器运行时（Docker/Podman） | cgroup + namespace 已够表达隔离 |
| 多云/集群编排 | 单机智能体运行时；多机交给外部系统 |
| 先做 aarch64/游戏/专业软件 | 会稀释 L1；x86_64 先做透，多架构等 OEM/教育明确需求 |

## 未决问题（需要决策）

1. **配置格式**：目前是 JSON（为了少一个依赖）。是否值得为可读性引入 TOML？
2. **智能体身份**：现在所有智能体都以 root 跑，靠 cgroup 限制。是否要引入
   `shuios-agent` 系统用户 + 每智能体 UID？
3. **模型来源**：是否内置模型下载器（需要信任根与签名校验），还是坚持
   "用户自己放文件进 `/var/lib/shuios/models`"？
4. **`shui` 的模型协议**：目前是"让模型输出 JSON 工具调用"，比原生
   function calling 弱。是否值得等本地推理支持 tool_calls 后切换？
5. **浏览器路线复核（原“浏览器怎么办”已落地）**：`shui-browser`（WebKitGTK 2.48）
   已在 V18 实测通过起始页/网页/下载/错误页。但 WebKit 仍有边界：DRM、
   部分办公/银行网站兼容、软件渲染性能、无沙箱。是否引入 Chromium/WPE、
   Wine、远程桌面兜底？见 [`09`](09-产品规划与市场调研.md) §10 第 6 项。
6. **产品化决策（需在 90 天内拍板）**：滩头客群、桌面技术路线、安装器路线、
   商业模式、是否做“运行时层”。音频栈已定为 PipeWire 并于 V26 交付，不再悬置。
   选项、建议与理由见 [`09`](09-产品规划与市场调研.md) §10。
